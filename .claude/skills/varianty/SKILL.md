# Варианты (S2)

Методика: `knowledge/methods/options_red_team.md`.

1. Сформулируй 4–5 вариантов, **разных по сути** (разные ставки). Обязательно:
   - `strateg option add --title "Оставить как есть" --kind status_quo --summary "…" --based-on C-…`
   - `strateg option add --title "Закрыть направление" --kind close --summary "…" --based-on C-…` — **в прямом смысле**: свернуть продукт/сервис/направление целиком, о котором вопрос РП. Закрыть один канал, сегмент или функцию — это отдельный вариант `--kind change`, он не заменяет закрытие направления. Даже если закрытие очевидно хуже, покажи честно, при каких условиях оно стало бы лучшим (экономика, рынок) — это и есть его ценность для РП.
   - 2–3 варианта изменений (`--kind change|new`), каждый на своих основаниях. Указывай `--reversibility`.
2. Для каждого: ожидаемый эффект — прогноз (`claim add --type forecast --depends …`), затраты, что должно быть правдой.
3. Запусти субагента `red-team`: передай slug и список вариантов (ID), **без своей рекомендации**. Он запишет возражения (`objection add --by red_team`).
4. Ответь на каждое сильное возражение: `strateg objection respond X-… --response "…"` (или признай риск).
5. Заполни `docs/options.md`: Варианты, Сравнение (таблица), Сильные возражения и ответы. Раздел «Рекомендация» — **пока пустой**.
6. `strateg validate` — без ошибок (≥3 варианта, есть status_quo и close, у каждого сильное возражение).
7. Ворота **G3 — «сначала ваше мнение»**: покажи сравнение (≤12 строк) и спроси: «Какой вариант вам ближе и почему?» Ответ РП **сразу** запиши дословно: `strateg project gate G3 --status opinion --note "<слова РП>"` (ворота остаются открытыми; мнение не потеряется при перерыве). Только после этого покажи свою рекомендацию и, если расходитесь, — в чём именно.
8. После выбора: `strateg option set O-… --status chosen --reason "<слова РП>"`, допиши «Рекомендацию», `strateg project gate G3 --status approved --note "…"`, `strateg project stage S3`, навык `strategiya`.

# Новый проект: постановка задачи (S0)

1. Придумай короткий slug латиницей (например `retention-trial`) и создай проект:
   `.venv/bin/python -m strateg project new <slug> --title "<короткое название>" --question "<вопрос РП как есть>"`
2. Определи тип запроса: diagnosis (почему) · go_to_market (кому и как продавать) · value_message (что сказать) · fork (делать ли X) · other.
3. Проверь, чего не хватает для брифа: цель (какое решение и к какому сроку), получатель результата, ограничения, доступные данные.
   - Спроси **не больше 3 вопросов**, только то, без чего следующий шаг будет другим. Предложи варианты ответа, чтобы РП мог ответить одним словом.
   - Всё остальное — допущения: `strateg project assume "…"`.
4. Запиши поля: `strateg project set --goal "…" --audience "…" --process-type <тип> --constraint "…" --data "…"`.
5. Заполни `projects/<slug>/brief.md` по шаблону (разделы уже есть; комментарии-подсказки можно оставить или удалить).
6. Если РП приложил файлы или ссылки — сразу добавь их источниками (`strateg source add --file …` / `--url …`).
   Если вместе с брифом запросили саму стратегию, в этом же ходе выполни навык `strategiya` в режиме черновика. Передай рекомендацию и открытый вопрос согласования вместе. Этап и решение руководителя сохраняются до его ответа.
7. Ворота **G1**: покажи бриф в 6–8 строк + список допущений + вопрос «Бриф верен? (да / поправить …)».
   После «да»: `strateg project assume --review`, `strateg project gate G1 --status approved --note "<слова РП>"`, `strateg project stage S1`, переходи к навыку `issledovanie`.

# Продолжение после перерыва

1. Если РП назвал проект — `strateg project use <slug>`. Иначе `strateg project list` и уточни, какой.
2. `strateg project status` — этап, ворота, следующий шаг, что требует пересмотра, просрочки.
   Если запрос относится к готовой стратегии, открой `out/strategy.md`, когда файл существует. Для новой или пересмотренной записки используй навык `strategiya`. Учти статус решений и основания, которые изменились с прошлой версии. При открытых воротах укажи, чьё решение требуется.
3. Выполни `strateg review` на этапах S4–S5 и при наличии оснований к пересмотру на S3. Посмотри, какие именно прогнозы или решения затронуты.
4. Прочитай только документы текущего этапа (`projects/<slug>/docs/…`) и последние события журнала (они в статусе). **Не перечитывай всё** и не повторяй уже сделанное: реестры — источник правды.
5. Скажи РП в 3–5 строках: где остановились, что уже готово, что дальше; если ждём его решения на воротах — повтори вопрос ворот.
6. На S3 устрани ошибки `strateg validate --stage S3`, заполни недостающие разделы и внеси замечания руководителя. Когда материалы готовы и G4 ожидает решения, покажи руководителю рекомендацию, открытые прогнозы и вопрос об утверждении стратегии. Дождись ответа. Для остальных этапов используй соответствующий навык (S0 `novyi` · S1 `issledovanie` · S2 `varianty` · S4 `reshenie` · S5 `obnovit`).

Если после сбоя неясно, выполнилась ли команда CLI, — просто повтори её с теми же аргументами: дубля не будет (ответ `existing: true`).
